# Decisions: 병아리 대포 React 전환 및 그래픽 개선

- Date: 2026-10-20
- Status: Confirmed
- Source: `C:\Users\유진서\Desktop\병아리대포_html.html`

## D01. 이전 범위
- **Chosen**: 기존 게임의 주요 기능을 유지하면서 React 앱으로 이전하고 그래픽을 구체화한다.
- **Rationale**: 현재 게임의 플레이와 스테이지 콘텐츠를 기반으로 개선한다.

## D02. 그래픽 스타일
- **Chosen**: 따뜻한 색감과 둥근 형태, 레이어 배경을 갖춘 동화책풍 2D 일러스트.
- **Rationale**: 기존 캐릭터와 세계관을 살리면서 화면의 시각적 완성도를 높인다.

## D03. 렌더링 및 그래픽 에셋
- **Chosen**: 프로젝트 내에서 제작한 SVG 에셋으로 캐릭터·배경 요소를 표현하고, 물리 오브젝트는 Canvas에서 렌더링한다.
- **Rationale**: 일러스트의 디테일과 물리 시뮬레이션을 함께 유지하고 에셋을 일관되게 관리한다.

## D04. 앱 기술 구성
- **Chosen**: React, TypeScript, Vite.
- **Rationale**: 타입을 활용해 게임 상태와 물리 데이터 구조를 관리하고 프론트엔드 개발을 단순하게 시작한다.

## D05. 화면 및 입력 지원
- **Chosen**: 데스크톱과 모바일을 지원한다. 데스크톱에서는 마우스, 모바일에서는 터치로 조작하며 세로 화면에도 게임 화면을 맞춘다.
- **Rationale**: 첨부 게임의 마우스·터치 입력을 이어받으면서 기기 범위를 넓힌다.

## D06. 물리 엔진
- **Chosen**: Matter.js를 유지하고 npm 패키지로 관리한다.
- **Rationale**: 기존 충돌과 구조물 물리 동작을 활용한다.

## D07. 캠페인 진행 구조
- **Chosen**: 현재 4개 챕터와 엔딩을 유지하며, 병아리 진화와 스테이지별 보스·장애물 및 구출 흐름을 이어간다.
- **Rationale**: 기존 게임의 핵심 진행 콘텐츠를 보존한다.

## D08. SVG 제작 방식
- **Chosen**: 게임에 맞춘 SVG 에셋을 프로젝트 안에서 직접 제작한다.
- **Rationale**: 스타일을 통일하고 게임에 맞춰 에셋을 수정하기 쉽게 한다.

## D09. 캠페인 진행 상황 저장
- **Chosen**: 진행 중인 캠페인 상태는 저장하지 않는다. 게임을 다시 열면 처음부터 시작한다. 온라인 순위 기록은 별도로 저장한다.
- **Rationale**: 첨부 HTML의 캠페인 초기화 동작을 유지하면서 순위표 기능을 추가한다.

## D10. Azure 아키텍처
- **Chosen**: Azure Static Web Apps에 React 앱을 호스팅하고, Azure Functions API와 Azure SQL Database로 온라인 순위를 제공한다.
- **Rationale**: 클라이언트와 순위 API 및 영구 데이터 저장을 분리하고, 공용 순위를 여러 플레이어에게 제공한다.

## D11. 로컬 개발 데이터 저장
- **Chosen**: 로컬 API는 메모리에 순위 데이터를 보관한다. Azure 배포 환경에서는 Azure SQL Database에 저장한다.
- **Rationale**: 로컬 개발 구성을 단순하게 유지한다. 메모리 데이터는 API 재시작 시 사라진다.

## D12. 순위 점수 기준
- **Chosen**: 4개 챕터 캠페인을 완료한 뒤 제출한 최종 점수로 전체 순위를 매긴다.
- **Rationale**: 완주 결과를 기준으로 플레이어 간 성적을 비교한다.

## D13. 닉네임 입력 및 기억
- **Chosen**: 최초 순위 등록 시 닉네임을 입력하고, 같은 브라우저에서 다음 기록을 위해 기억한다.
- **Rationale**: 계정 가입 없이 기록 제출을 간편하게 한다.

## D14. 참가자 식별 및 중복 닉네임
- **Chosen**: 같은 닉네임을 허용한다. 브라우저별 참가자 ID를 두어 서로 다른 참가자로 구분한다.
- **Rationale**: 계정 가입 없이 닉네임 소유권을 확인하기 어렵기 때문에 중복을 막지 않는다.

## D15. 반복 완주 기록
- **Chosen**: 참가자별 최고 캠페인 점수 하나만 순위에 남기며, 새 점수가 더 높으면 갱신한다.
- **Rationale**: 한 참가자가 순위표 여러 자리를 차지하지 않도록 한다.

## D16. 순위표 접근 및 공유 범위
- **Chosen**: 순위표는 게임 안에서 모든 플레이어에게 공개한다. 외부 공유 링크나 공유 이미지 기능은 제공하지 않는다.
- **Rationale**: 공용 순위를 게임 안에서 함께 보되 별도 공유 기능은 추가하지 않는다.

## D17. 순위표 진입 지점
- **Chosen**: 메인 화면과 캠페인 완료 화면에서 순위표를 열 수 있다.
- **Rationale**: 플레이 전후로 순위를 확인할 수 있다.

## D18. 순위표 목록 범위
- **Chosen**: 전체 참가자 기록을 점수 순으로 제공하고 페이지 단위로 탐색한다.
- **Rationale**: 상위 일부에 제한하지 않고 모든 순위를 볼 수 있게 한다.

## D19. 서버 점수 검증
- **Chosen**: 캠페인 완료 후에만 점수를 제출하고, 서버에서 점수 범위와 요청 빈도를 기본 검증한다.
- **Rationale**: 구현 범위를 유지하면서 잘못된 점수와 반복 요청을 제한한다.

## D20. Azure 배포 준비 범위
- **Chosen**: React 앱·API·데이터베이스의 Azure 배포 설정과 안내를 준비하되, 실제 Azure 리소스 생성과 배포는 별도로 진행한다.
- **Rationale**: 사용자가 Azure 배포를 이어갈 수 있는 구성을 마련하되 실제 계정의 리소스 변경은 범위에 넣지 않는다.
